Poziom: Zaawansowany

<h1> Brak dostępności konfiguracji CRU API przypisanej do innego stanowiska </h1>

<h2> Cel testu </h2>

Celem testu jest sprawdzenie scenariusza: Brak dostępności konfiguracji CRU API przypisanej do innego stanowiska.

<h2> Rozdział dokumentacji </h2>

Konfiguracja CRU API — token per stanowisko, konfiguracje aktywne/nieaktywne oraz wybór konfiguracji dla umowy

<h2> Warunki wstępne </h2>

- System EZD jest uruchomiony i dostępny.
- Użytkownik jest zalogowany do systemu EZD.
- Użytkownik posiada rolę RejestUmowModyfikacjaDodaj.
- W systemie istnieją konfiguracje CRU API przygotowane zgodnie ze scenariuszem.
- Istnieje aktywna konfiguracja przypisana do innego stanowiska/użytkownika niż aktualne.
- Użytkownik ma dostęp do więcej niż jednej innej aktywnej konfiguracji, aby pole „Konfiguracja CRU” było widoczne.

<h2> Kroki testowe </h2>

| Krok | Czynność | Oczekiwany rezultat |
|---:|---|---|
| 1 | Otwórz formularz „Dodaj umowę” na aktualnym stanowisku. | Formularz zostaje wyświetlony. |
| 2 | Rozwiń pole „Konfiguracja CRU”. | System prezentuje konfiguracje dostępne dla bieżącego stanowiska. |
| 3 | Wyszukaj konfigurację przypisaną do innego stanowiska/użytkownika. | Konfiguracja przypisana do innego stanowiska/użytkownika nie jest dostępna na liście. |

<h2> Kryteria akceptacji </h2>

- Wszystkie kroki testowe kończą się rezultatem zgodnym z oczekiwaniem.
- Stan konfiguracji lub przypisania pozostaje zgodny po odświeżeniu widoku.
- System nie udostępnia konfiguracji CRU poza zakresem wynikającym z jej statusu oraz przypisania do użytkownika i stanowiska.
