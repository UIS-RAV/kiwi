<h1> Przypisanie konfiguracji CRU API do stanowiska podczas edycji </h1>

<h2> Cel testu </h2>

Celem testu jest sprawdzenie scenariusza: Przypisanie konfiguracji CRU API do stanowiska podczas edycji.

<h2> Rozdział dokumentacji </h2>

Konfiguracja CRU API — token per stanowisko, konfiguracje aktywne/nieaktywne oraz wybór konfiguracji dla umowy

<h2> Warunki wstępne </h2>

- System EZD jest uruchomiony i dostępny.
- Użytkownik jest zalogowany do systemu EZD.
- Użytkownik posiada uprawnienia do Administracja → Ustawienia Ogólne → Rozszerzenia → Ustawienia rozszerzeń → CRU.
- Istnieje aktywna konfiguracja ogólna oznaczona jako domyślna.
- Istnieje aktywne stanowisko z powiązanym użytkownikiem.

<h2> Kroki testowe </h2>

| Krok | Czynność | Oczekiwany rezultat |
|---:|---|---|
| 1 | W zakładce „Aktywne” wybierz „Edytuj” w kolumnie „Należy do” konfiguracji domyślnej. | System wyświetla listę aktywnych stanowisk z użytkownikami oraz przyciski Zapisz i Anuluj. |
| 2 | Wskaż stanowisko i użytkownika. | Wybrana wartość jest widoczna w polu. |
| 3 | Wybierz „Zapisz”. | System zapisuje przypisanie i odświeża ekran. |
| 4 | Zweryfikuj kolumnę „Należy do”. | Widoczne jest wskazane stanowisko i użytkownik. |
| 5 | Zweryfikuj „Domyślna konfiguracja”. | Po przypisaniu do stanowiska atrybut konfiguracji domyślnej zostaje ustawiony na brak. |

<h2> Kryteria akceptacji </h2>

- Wszystkie kroki testowe kończą się rezultatem zgodnym z oczekiwaniem.
- Stan konfiguracji lub przypisania pozostaje zgodny po odświeżeniu widoku.
- System nie udostępnia konfiguracji CRU poza zakresem wynikającym z jej statusu oraz przypisania do użytkownika i stanowiska.
