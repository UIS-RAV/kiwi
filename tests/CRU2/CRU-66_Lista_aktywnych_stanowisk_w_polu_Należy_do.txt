<h1> Lista aktywnych stanowisk w polu Należy do </h1>

<h2> Cel testu </h2>

Celem testu jest sprawdzenie scenariusza: Lista aktywnych stanowisk w polu Należy do.

<h2> Rozdział dokumentacji </h2>

Konfiguracja CRU API — token per stanowisko, konfiguracje aktywne/nieaktywne oraz wybór konfiguracji dla umowy

<h2> Warunki wstępne </h2>

- System EZD jest uruchomiony i dostępny.
- Użytkownik jest zalogowany do systemu EZD.
- Użytkownik posiada uprawnienia do Administracja → Ustawienia Ogólne → Rozszerzenia → Ustawienia rozszerzeń → CRU.
- W strukturze istnieją aktywne stanowiska z użytkownikami oraz co najmniej jedno stanowisko nieaktywne.

<h2> Kroki testowe </h2>

| Krok | Czynność | Oczekiwany rezultat |
|---:|---|---|
| 1 | Otwórz formularz nowej konfiguracji CRU API. | Formularz zostaje wyświetlony. |
| 2 | Rozwiń pole „Należy do”. | System prezentuje listę aktywnych stanowisk z powiązanymi użytkownikami. |
| 3 | Zweryfikuj format pozycji listy. | Pozycje mają format NAZWA STANOWISKA (SYMBOL KOMÓRKI) – IMIĘ NAZWISKO. |
| 4 | Zweryfikuj brak stanowiska nieaktywnego. | Nieaktywne stanowisko nie jest dostępne do wyboru. |
| 5 | Pozostaw pole puste. | System dopuszcza brak wartości, ponieważ pole nie jest wymagane. |

<h2> Kryteria akceptacji </h2>

- Wszystkie kroki testowe kończą się rezultatem zgodnym z oczekiwaniem.
- Stan konfiguracji lub przypisania pozostaje zgodny po odświeżeniu widoku.
- System nie udostępnia konfiguracji CRU poza zakresem wynikającym z jej statusu oraz przypisania do użytkownika i stanowiska.
