<h1> Dodanie kolejnego stanowiska do konfiguracji CRU API </h1>

<h2> Cel testu </h2>

Celem testu jest sprawdzenie scenariusza: Dodanie kolejnego stanowiska do konfiguracji CRU API.

<h2> Rozdział dokumentacji </h2>

Konfiguracja CRU API — token per stanowisko, przypisane stanowiska i wybór konfiguracji dla umowy

<h2> Warunki wstępne </h2>

- System EZD jest uruchomiony i dostępny.
- Użytkownik jest zalogowany i posiada dostęp do konfiguracji CRU API.
- Konfiguracja CRU API ma już przypisane co najmniej jedno konkretne stanowisko.

<h2> Kroki testowe </h2>

| Krok | Czynność | Oczekiwany rezultat |
|---:|---|---|
| 1 | Uruchom edycję pola „Przypisane stanowiska”. | System prezentuje istniejące przypisania i listę aktywnych stanowisk. |
| 2 | Wybierz inne aktywne stanowisko niż już przypisane. | Nowe stanowisko zostaje wskazane. |
| 3 | Wybierz „Zapisz”. | System dopisuje nowe stanowisko do wcześniej istniejących przypisań. |
| 4 | Zweryfikuj listę przypisanych stanowisk. | Lista zawiera zarówno wcześniejsze, jak i nowo dodane stanowisko. |

<h2> Kryteria akceptacji </h2>

- Wszystkie kroki testowe kończą się rezultatem zgodnym z oczekiwaniem.
- Stan konfiguracji pozostaje zgodny po odświeżeniu lub ponownym otwarciu widoku.
- Dostęp do konfiguracji wynika z przypisania do stanowiska oraz reguł określonych w dokumentacji.
