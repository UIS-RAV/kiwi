<h1> Walidacja niepoprawnych danych interesanta w imporcie </h1>

<h2> Cel testu </h2>

Celem testu jest weryfikacja scenariusza: Walidacja niepoprawnych danych interesanta w imporcie.

<h2> Rozdział dokumentacji </h2>

SD — SYSTEMY DZIEDZINOWE — Import z SD, adresy ADE, metody wysyłki i aktualizacja danych interesantów

<h2> Warunki wstępne </h2>

- System EZD jest uruchomiony i dostępny.
- Endpoint API systemu dziedzinowego jest dostępny, o ile scenariusz nie zakłada jego niedostępności.
- Dostępne są dane autoryzacyjne odpowiednie dla scenariusza.
- Użytkownik integracyjny posiada stanowisko z rolami API-SD i API-Dokument, o ile scenariusz nie dotyczy braku uprawnień.
- Dostępne są dane testowe umożliwiające jednoznaczne wyszukanie sprawy, dokumentu i interesanta.

<h2> Kroki testowe </h2>

| Krok | Czynność | Oczekiwany rezultat |
|---:|---|---|
| 1 | Wyślij interesanta z niepoprawnym identyfikatorem, kodem pocztowym lub adresem e-mail. | API zwraca błąd walidacji właściwego pola. |
| 2 | Sprawdź dane w EZD. | Nie utworzono ani nie zaktualizowano błędnego rekordu. |

<h2> Kryteria akceptacji </h2>

- Wszystkie kroki testowe kończą się rezultatem zgodnym z oczekiwaniem.
- System nie tworzy niekontrolowanych duplikatów ani niespójnych powiązań.
- Stan końcowy pozostaje zgodny po odświeżeniu i ponownym otwarciu danych.
